# MyDataStructures

Учебный проект: собственные аналоги контейнеров STL, написанные вручную, чтобы разобраться, как они устроены «под капотом». Не претендует на production-качество и не является заменой `std::vector` / `std::list` / `std::set`.

## Что внутри

- **`vector`** — динамический массив.
- **`list`** — двусвязный список.
- **`bst_tree`** — бинарное дерево поиска (без балансировки).

Все контейнеры лежат в `src/`, объединены в namespace `MyDataStructures` (псевдоним `mds`). Подключаются через `MyDataStructures.h`.

## Структура

    MyDataStructures/
    ├── src/
    │   ├── vector.h
    │   ├── list.h
    │   ├── bst_tree.h
    │   ├── MyDataStructures.h      # агрегирующий заголовок
    │   ├── MyDataStructures.cpp    # точка входа тестового раннера
    │   └── main_MyDataStructures.cpp
    ├── tests/
    │   ├── test_vector.cpp
    │   ├── test_list.cpp
    │   └── test_bst_tree.cpp
    ├── googletest/                 # вендорная копия GoogleTest
    └── CMakeLists.txt

## Сборка и запуск тестов

Проект собирается через CMake. GoogleTest уже лежит в `googletest/`, отдельно ставить ничего не нужно.

    cmake -S . -B out
    cmake --build out
    ./out/MainApp

`MainApp` — это тестовый раннер: внутри `main` вызывает `testing::InitGoogleTest` и `RUN_ALL_TESTS`. Все тесты из `tests/` линкуются в этот исполняемый файл.

## Статус

Проект учебный и находится в активной доработке. На данный момент:

- `vector` — move-семантика, `reserve`, `clear`, `pop_back` приведены в порядок, добавлена защита от self-assignment. Поведение ориентировано на контракт `std::vector` (в частности, `pop_back` требует непустого контейнера, в Debug срабатывает `assert`).
- `list` — базовая функциональность есть, но есть известные проблемы в граничных случаях (`push_back`/`push_front` в пустой список, `pop_back`/`pop_front` на одном элементе, `insert`/`erase`). Будет исправляться отдельно.
- `bst_tree` — вставка, поиск, удаление; есть известные проблемы с удалением узла с двумя детьми и копированием пустого дерева.

## Тесты

Тесты написаны на GoogleTest. Текущее покрытие — в основном «счастливый путь»: контейнер наполняется, потом проверяются операции. Граничные сценарии (пустой контейнер, один элемент, `clear()` + `push_back`, self-assignment, копирование пустого, нетривиальный `T`) пока покрыты слабо. Это осознанный долг: следующие шаги — добавить тесты именно на эти случаи и включить санитайзеры (`-fsanitize=address,undefined`) для тестового таргета, чтобы утечки и use-after-free не молчали.

## Ограничения

- Память в `vector` выделяется через `malloc`/`free`, без вызова конструкторов и деструкторов `T`. Для `int` это работает, для нетривиальных типов (`std::string` и т.п.) — неопределённое поведение. Это известное ограничение учебной реализации, а не баг «на сейчас».
- `bst_tree` не балансируется: на отсортированных данных вырождается в список.
- API не полностью совместим со STL: местами `operator=` возвращает `void`, методы не помечены `const`, нет `const_iterator` и т.д.

## Зачем это

Цель — не заменить STL, а понять, как он устроен: как работает рост `vector`, как устроены итераторы `list`, как удаляется узел в BST. Поэтому код намеренно простой и читаемый, а не оптимизированный.
